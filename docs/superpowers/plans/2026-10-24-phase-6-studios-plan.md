## What a studio is

A studio is a full-page view of the current repository that replaces the board under the same top bar. A nav `Studios` (Board, Document, Diagram, Code, Vault) sits in the top bar; the active studio is the URL hash (`#/document`, `#/diagram`, `#/code`, `#/vault`; no hash = board). The board unmounts while a studio is open; the daemon keeps every console running and its ring buffer replays on return. Every studio works on files inside the repository so the result survives without AgentBoard: a document is `docs/<name>.md`, a diagram is `docs/<name>.diagram.json`, the vault is `docs/vault/**/*.md`, pins are in the board file. Agents do the writing: a studio spawns or steers an ordinary console (POST /api/consoles with a prompt, POST /api/consoles/:id/input) and renders the file the agent writes. The studio never calls a model itself.

Design rules for this phase (P6-D45 to P6-(P6-D49) on issue #27):

- One new runtime dependency for the whole phase: `marked` (markdown to HTML) in packages/ui, exact version, added by L60. Everything else is the stack already on main.
- PDF export is the browser's print dialog over a print stylesheet (`@page`, page breaks before `h2`, a page-number footer through CSS counters). No PDF library.
- PNG export is SVG to canvas to blob in the browser. The `.excalidraw` export is a converter from the diagram JSON. No drawing library.
- Code previews are plain `<pre>` with line numbers. No highlighter.
- The link graph is the current note in the centre and its neighbours on a circle, drawn as SVG. No layout library.

## Contracts L60 fixes (every later lane codes against these names)

Routes added to `packages/shared/src/routes.ts`, schemas beside them in `schemas.ts`, a fixture each under `fixtures/`:

| Route | Request | Response |
| --- | --- | --- |
| GET /api/files | FilesQuerySchema `{repo, path?}` (one directory, lazy tree) | FileTreeSchema `{path, entries: [{name, path, kind: "file" or "dir", status?: "M", "A", "D" or "?"}]}` |
| GET /api/files/read | FilesQuerySchema | FileContentSchema `{path, size, lines, text: string or null (null when binary or over 1 MB), language}` |
| PUT /api/files/write | FileWriteRequestSchema `{repo, path, text}` | OkSchema |
| POST /api/consoles/:id/input | ConsoleInputSchema `{data}` | OkSchema |
| GET /api/vault/notes | VaultQuerySchema `{repo}` | VaultIndexSchema `{root, notes: [{path, title, folder, mtime, links: string[], backlinks: string[]}]}` |
| GET /api/vault/note | VaultNoteQuerySchema `{repo, path}` | VaultNoteSchema `{path, title, text, mtime, links: string[], backlinks: [{path, title, excerpt}]}` |
| PUT /api/vault/note | VaultWriteSchema `{repo, path, text, mtime?}` (409 when mtime moved) | VaultNoteSchema |
| POST /api/vault/append | VaultAppendSchema `{repo, path, text, author}` | VaultNoteSchema |

Paths in every request are repository-relative, POSIX separators; the daemon resolves them under `repo`, refuses `..`, absolute paths, anything that resolves outside the repository or inside `.git/`, and symbolic links that leave it. `repo` must be a board the daemon has loaded (same rule as `GET /api/board`).

BoardSchema gains `studio: z.object({ pins: z.array(z.string()).default([]), document: z.string().optional(), diagram: z.string().optional() }).optional()`: pinned file paths, and the paths of the document and diagram last opened.

Daemon wiring: `packages/daemon/src/files/index.ts` exports `createFileHandlers(deps)` and `packages/daemon/src/vault/index.ts` exports `createVaultHandlers(deps)`, each returning the handlers for its routes; app.ts spreads both into `routes`. L60 ships them as stubs that throw `HttpError(501, "not built yet")` with a test per stub; L61 and L63 replace the stubs without touching app.ts. `POST /api/consoles/:id/input` is implemented in app.ts by L60: `pty.write(id, data)` for a running console, 404 otherwise.

UI shell in `packages/ui/src/studios/`: `index.tsx` exports `StudioTabs` (a `nav` with `aria-label="Studios"` and five buttons, the active one `aria-current="page"`), `useStudio()` (the active studio id from `location.hash`, updated on `hashchange`), and `studios`, a record from id to component; `context.ts` exports `StudioContext` with `{ repo, fetch, consoles, board, saveBoard, sendInput(consoleId, text), spawn(prompt, opts) }`; `markdown.ts` exports `renderMarkdown(text): string` over `marked` with HTML in the source escaped, and `headings(text): {level, text, line}[]`; `code/CodeStudio.tsx`, `vault/VaultStudio.tsx`, `document/DocumentStudio.tsx`, `diagram/DiagramStudio.tsx` as stubs rendering an `h1` with the studio name and the line "Coming in lane L6x". app.tsx renders `studios[active]` in place of `Board` when a hash names one; the mission map rail and the top bar stay.
