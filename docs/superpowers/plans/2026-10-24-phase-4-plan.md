# AgentBoard Phase 4: Orchestration and Continuity

**Goal:** Mission map, teams with roles, handoff briefs, loops, a composer, account profiles, token analytics from local logs and per-repo project memory, built as 16 worker lanes under the same governor loop, gate and review as phases 0 to 2 (`2026-10-23-multi-agent-build-plan.md`). Spec rows: "Orchestration" and "Continuity" in `docs/superpowers/specs/2026-10-23-agentboard-design.md`; phase 4 gate: a real handoff and a real loop ship work; analytics match the CLI's own numbers within 5 percent.

**Design reference:** the owner's mockups, one per screen, copied from the design canvas into `docs/design/mockups/phase-4/*.dc.html` (Mission-Map, Teams, Handoff, Loops, Composer, Usage, Memory). They are the look and the vocabulary; the task cards below are the behaviour. Tokens, fonts and the per-agent marks already exist in `packages/ui/src/styles/tokens.css` (D44, L29). A mockup detail the card does not name is direction, not scope.

## Rules that carry over

Every rule of the MVP plan and CLAUDE.md holds: TypeScript strict, Vitest first, exact dependency versions with a one-line reason, `scripts/gate.sh` before a PR, no secrets or home paths in files or PR bodies, never run third-party agent binaries (the fake agent in `packages/e2e/fake-agent` stands in), never answer a permission prompt from code. Two rules are new:

- **Shared wiring files.** `packages/daemon/src/app.ts` and `packages/ui/src/app.tsx` are wiring. A lane may add only its own mount lines there (an import, a module construction, a route handler entry that delegates to its module, a component in the layout). Logic lives in the lane's own directory. The governor resolves the rebase conflicts these lines cause.
- **Safety invariants for phase 4 (P4-D45).** Nothing a handoff, loop, composer or memory push does may answer a permission prompt: a prompt is only ever written into a PTY while the target console is `idle` (or freshly spawned); a target in `needs_you` refuses with 409 and the caller shows why. Loops pause while their console needs you and stop when it exits. Auto-approve flags are never added to a launch.

## Data that phase 4 adds (L40 fixes the exact shapes)

- On the board file (`Workspace.teams`): teams. Everything else lives beside it under `~/.agentboard/`: `handoffs/<id>.md` and `handoffs.json`, `loops.json`, `events/<yyyy-mm-dd>.jsonl` (7 days), `usage.json` (parser cache, D46), `memory/global.json` and `memory/<repo-hash>.json`. Settings gain `profiles`, `composerTemplates` and `memory.offerAtSpawn`.
- Contracts live in `packages/shared` as zod schemas, a routes table entry per endpoint and a fixture per shape, as in phase 0 to 2.

## Decisions recorded for this plan (issue #27)

- P4-D45 safety invariants above.
- P4-D46 the usage cache is JSON under `~/.agentboard`, not sqlite: no native dependency for a few megabytes of aggregates.
- P4-D47 handoff briefs are extracted deterministically from the transcript, with no model call; the user edits the brief before sending.
- P4-D48 the cron parser is hand-rolled (5 fields); no scheduling dependency.
- P4-D49 teams live on the board file; loops, handoffs, memory and events live in their own files under `~/.agentboard`.
- P4-D50 the mission map covers the open repo's workspaces; the mockup's "All repos" filter waits until the daemon serves several boards at once.
- P4-D51 several governors share this checkout and PARALLEL 8 (phase 1 redesign L1D to L1G, phase 2 design L2A to L2C, phase 3 L30 to L37, phase 5 L50 to L56, a phase 6 draft); phase 4 counts every running session before dispatching, and L41 starts after L1D so the top bar is redesigned once. L41's `registerView` is offered to phase 5 and 6 as the one place top-level views mount.
