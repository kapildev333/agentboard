# Phase 3 Plan: Board Extras

> **For agentic workers:** the same rules as the MVP plan (`2026-10-23-multi-agent-build-plan.md`): one lane per worktree, failing test first, `scripts/gate.sh` before the PR, no merge by a worker, decisions recorded on issue #27.

**Goal:** the board holds more than consoles: a web tile with a localhost preview and a console inspector, sticky notes, markdown text, checklists, dropped images, an ink layer and layout presets (spec, "Later phases", phase 3). Gate: the preview and the notes are used daily, an owner check.

**Design reference:** the "03 · Board extras" row of the AgentBoard Screens canvas (artboard "Board extras · web tile, notes, ink, presets"): a web tile with an address bar, status chip and an Inspector with Console, Network and Elements tabs; an image node; a markdown text node with Edit; a checklist with a done count; a sticky note; a Layout presets menu (2×2 grid ⌘⇧1, one row ⌘⇧2, preview + consoles ⌘⇧3, focus one ⌘⇧4, Save current layout…). Tokens are the ones in `packages/ui/src/styles/tokens.css`.

**What exists under it:** `NoteNodeSchema`, `WebTileNodeSchema` and `ChecklistNodeSchema` are already in `packages/shared/src/schemas.ts`; the page renders `note` nodes read-only and nothing for the other two. The board store, autosave, `rev` on PUT and the `board` broadcast (L1B) carry every new node kind without change.

## Rulings that shape this phase (issue #27)

- P3-D1 Phase 3 lands as eight lanes L30 to L37 in this plan file, issues created with `gh` (as phase 5 did, D51). L30 stacks on L50's branch because both edit `packages/shared`; L32 to L36 stack on L30; L31 runs from main; L37 closes the phase.
- P3-D2 The web tile is a plain iframe on the user's URL by default. "Devtools" means an opt-in Capture mode: the daemon proxies the page from a loopback target and injects one script that relays console, errors and fetch summaries to the board by `postMessage`. The proxy is reachable only by a key derived from the launch secret (never the secret itself), targets only loopback hosts, forwards no cookie or authorization header, and serves the page with a CSP that keeps it away from `/api/*`. Elements inspection is out of scope; the Inspector has Console and Network tabs.
- P3-D3 Images are stored by content hash under `AGENTBOARD_HOME/assets`, png, jpeg, gif and webp only (no svg: it can carry script), 10 MB cap, served through the token-gated API with immutable cache headers.
- P3-D4 Ink strokes and saved layouts live on the workspace in the board file (optional fields, so old boards load). Shortcuts (meta or ctrl plus shift plus 1 to 4, Escape) never fire while a terminal has focus.
- P3-D5 Several governors share the machine (phase 1 and 2 redesign lanes, phase 5): phase 3 keeps at most three lanes running while another phase has lanes running, up to PARALLEL when it is alone.

## The contract (L30 writes it; every other lane imports it)

In `packages/shared/src/extras.ts`, re-exported from `index.ts` (schemas.ts changes only where the unions are extended):

```ts
export const TextNodeSchema = z.object({ ...nodeBase, type: z.literal("text"), markdown: z.string() });
export const ImageNodeSchema = z.object({ ...nodeBase, type: z.literal("image"), assetId: z.string(), width: z.number().int().positive(), height: z.number().int().positive(), alt: z.string().default("") });
// WebTileNodeSchema gains: capture: z.boolean().optional()
export const StrokeSchema = z.object({ id: z.string(), points: z.array(z.tuple([z.number(), z.number()])).min(2), color: z.string(), width: z.number().positive() });
export const SavedLayoutSchema = z.object({ name: z.string().min(1), nodes: z.record(z.object({ x: z.number(), y: z.number(), w: z.number(), h: z.number() })) });
// WorkspaceSchema gains: ink: z.array(StrokeSchema).optional(), layouts: z.array(SavedLayoutSchema).optional()
// BoardNodeSchema's union gains TextNodeSchema and ImageNodeSchema
export const AssetUploadResponseSchema = z.object({ id: z.string(), width: z.number().int().positive(), height: z.number().int().positive() });
export const PreviewInfoSchema = z.object({ key: z.string().length(32) });
```

Routes added to `routes.ts`: `POST /api/assets` (raw image body with its Content-Type, response `AssetUploadResponseSchema`), `GET /api/assets/:id` (the bytes), `GET /api/preview` (response `PreviewInfoSchema`). The preview proxy itself is `GET /preview/<key>/<percent-encoded target url>` outside `/api`, documented in L32's card. Fixtures: `fixtures/extras.json` with one node of each new kind, a stroke and a saved layout.
