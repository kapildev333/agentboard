# L03 spike: xterm.js inside a React Flow node under zoom

Page: `packages/ui/spike` (Vite, React Flow, six xterm.js terminals on a 30-line echo WebSocket server).
Run: `npm run spike -w @agentboard/ui` for the page (add `?ws=<echo port>`; `?zoom=0.5`, `?renderer=webgl`), and `npx playwright test` from `packages/e2e` for the measurements below. The echo server is `node packages/ui/spike/echo-server.mjs`.

## Method and limits

Headless Chromium from Playwright 1.64.1 on macOS, WebGL through SwiftShader (software GL, no GPU), device pixel ratio 1, 1280x720 viewport, six nodes with a 480x300 terminal each. fps = `requestAnimationFrame` callbacks over two seconds while the mouse drags the empty pane (60 moves, about 300 px).

**The fps numbers cannot separate the renderers.** Headless Chromium caps rAF at 60, and six idle terminals draw almost nothing during a pan, so every cell is 50 to 60. They show the board stays smooth under zoom with six consoles; they do not show WebGL beating DOM. Re-measure on a real GPU with heavy output (L1A's six-console smoke) before treating the renderer choice as final. Retina (DPR 2) was not tested.

## Results (fps while panning, six consoles)

| Zoom | WebGL | DOM |
|-----:|------:|----:|
| 50%  | 54    | 57  |
| 100% | 54    | 60  |
| 150% | 51    | 60  |

Run to run these move by a few fps. DOM was at or above WebGL in every cell of every run I made.

## Blur under CSS scale

React Flow scales the node with `transform: scale()`; the terminal underneath does not know.

- **WebGL: soft at 150%.** Glyphs live in a texture atlas rasterised at 1x, and the browser upscales the finished canvas, so text is visibly blurred (`L03-webgl-150.png`). At 50% it is a downscale and reads fine (`L03-webgl-50.png`).
- **DOM: crisp at every zoom.** The browser rasterises real text at the scaled size (`L03-dom-150.png`, `L03-dom-50.png`).

## Input

Keystroke to echo in the buffer with six terminals open (default DOM renderer): median 4.8 ms, p95 5.5 ms (budget 50 ms), loopback only, so this is the page's own overhead, not a PTY's. Typing "hello" into the third node echoed correctly.

**Drag and focus (for L16).** `nodrag` is added when the terminal gets focus, and React Flow checks for it when a drag starts. If the whole node were the drag surface, the click that focuses the terminal would add `nodrag` first and the node could then never be dragged by its terminal. So the spike drags by a header (`dragHandle: ".drag-handle"`), and `nodrag nowheel` sit only on the terminal body while it is focused. L16 should do the same: a header or title bar as the handle, `nodrag nowheel` on the terminal element only. The spec drags node 1 by its header while its terminal is focused and checks that it moves.

## Cell size: why one renderer

At the same 480x300 node, WebGL floors the cell width and fits 66 columns; the DOM renderer fits 59 (measured, `term.cols`, same at every zoom). Switching renderers on a zoom crossing would therefore refit, resize the PTY and reflow a running agent each time, so the renderer must not change with zoom.

## Decision for L16

Use the DOM renderer at all zoom levels. It is crisp at every zoom, it was equal or faster in every measured cell (57, 60, 60 against 54, 54, 51 fps), input latency is the same, it needs no addon and no WebGL context (Chromium allows about 16 per page), and the column count never changes with zoom. WebGL stays a later option for output-heavy consoles, but it should be chosen once per console and measured on a real GPU first, not toggled with zoom. Options exactly as tested: `new Terminal({ fontSize: 13, fontFamily: "Menlo, monospace" })`, then `const fit = new FitAddon(); term.loadAddon(fit); term.open(el); fit.fit()`. No other options were set (xterm 6.0.0 defaults: DOM renderer, scrollback 1000). The page ships DOM by default; `?renderer=webgl` loads `new WebglAddon()` with defaults after `term.open` for comparison. Input is binary frames in, `term.write(new Uint8Array(buf))`, and `term.onData` sent as UTF-8 bytes. FitAddon measures layout pixels, which `transform: scale` does not change, so the refit on zoom end (`onMoveEnd`) keeps cols and rows at any zoom; it only matters once a node is resized.
