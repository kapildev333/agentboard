# L03 spike: xterm.js inside a React Flow node under zoom

Page: `packages/ui/spike` (Vite, React Flow, six xterm.js terminals on a 30-line echo WebSocket server).
Run: `npm run spike -w @agentboard/ui` for the page (add `?ws=<echo port>`; `?zoom=0.5`, `?renderer=dom`), and `npx playwright test` from `packages/e2e` for the measurements below. The echo server is `node packages/ui/spike/echo-server.mjs`.

## Method and limits

Headless Chromium from Playwright 1.64.1 on macOS, WebGL through SwiftShader (software GL, no GPU), device pixel ratio 1, 1280x720 viewport, six 480x300 nodes. fps = `requestAnimationFrame` callbacks over two seconds while the mouse drags the empty pane (60 moves, about 300 px).

**The fps numbers cannot separate the renderers.** Headless Chromium caps rAF at 60, and six idle terminals draw almost nothing during a pan, so every cell is 52 to 60. They show the board stays smooth under zoom with six consoles; they do not show WebGL beating DOM. Re-measure on a real GPU with heavy output (L1A's six-console smoke) before treating the renderer choice as final. Retina (DPR 2) was not tested.

## Results (fps while panning, six consoles)

| Zoom | WebGL | DOM |
|-----:|------:|----:|
| 50%  | 55.5  | 52  |
| 100% | 55    | 60  |
| 150% | 56    | 60  |

Run to run these move by a few fps; treat 52 to 60 as one band.

## Blur under CSS scale

React Flow scales the node with `transform: scale()`; the terminal underneath does not know.

- **WebGL: soft at 150%.** Glyphs live in a texture atlas rasterised at 1x, and the browser upscales the finished canvas, so text is visibly blurred (`L03-webgl-150.png`). At 50% it is a downscale and reads fine (`L03-webgl-50.png`).
- **DOM: crisp at every zoom.** The browser rasterises real text at the scaled size (`L03-dom-150.png`, `L03-dom-50.png`).

## Input

Keystroke to echo in the buffer with six terminals open: median 4.8 ms, p95 5.2 ms (budget 50 ms), loopback only, so this is the page's own overhead, not a PTY's. Typing "hello" into the third node echoed correctly. FitAddon measures layout pixels, which `transform: scale` does not change, so the refit on zoom end keeps the same cols and rows at any zoom; it is cheap and harmless, and it only matters once a node is resized. I did not write a test for the `nodrag`/`nowheel` classes appearing on focus.

## Decision for L16

Use the WebGL renderer, but only while the viewport zoom is 1 or below; at zoom above 1 dispose the WebglAddon and let xterm fall back to its DOM renderer, because WebGL text is blurry when scaled up and DOM text is not, and the measured speed gap is nil here. Re-attach WebGL when zoom returns to 1 or below. Options: `new Terminal({ fontFamily: "Menlo, monospace", fontSize: settings.fontSize, scrollback: 5000, cursorBlink: false, allowProposedApi: false })`, then `term.loadAddon(fit)`, `term.open(el)`, and `const gl = new WebglAddon(); gl.onContextLoss(() => gl.dispose()); term.loadAddon(gl)` (default `preserveDrawingBuffer: false`). Chromium allows roughly 16 live WebGL contexts per page, so L16 should hold a WebGL addon only for visible nodes and dispose it for off-screen ones. Gate it on the current zoom from React Flow's `onMoveEnd`, and call `fit.fit()` there too. Binary frames in, `Uint8Array` to `term.write`, as the spike does.
