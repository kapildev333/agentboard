## Codex

- **Installed here:** the npm package `@openai/codex` 0.53.0 is on PATH (`/usr/local/bin/codex`), but macOS blocks the binary on launch, so nothing below was run live. Evidence is `strings` on the shipped binary (it contains `agent-turn-complete`, `thread-id`, `turn-id`, `input-messages`, `last-assistant-message`, `CODEX_HOME`, "Failed to resume session from") plus Codex's documentation. **Verify live on a machine where it runs** (see "To verify").
- **Per-launch hook:** yes. Any `config.toml` key can be overridden with `-c key=value` (value parsed as TOML). `codexLaunch` passes `-c 'notify=["<process.execPath>","<abs>/notify-relay.js"]'`. `CODEX_HOME=<dir>` with a generated `config.toml` is the fallback, but it moves auth and sessions too, so `-c` is preferred. No edit to `~/.codex` is needed; the opt-in config edit (F2.2) is not required for Codex. Caveat: `-c notify=` replaces, it does not add to, any `notify` the user already set in their own `config.toml`, so their own notification program does not run in AgentBoard consoles.
- **Resume:** `codex resume <SESSION_ID>` (also `codex resume --last`). `-c` still works after it.
- **Session id:** Codex cannot be told an id at start. It writes `$CODEX_HOME/sessions/YYYY/MM/DD/rollout-<timestamp>-<uuid>.jsonl` (default `~/.codex/sessions`); the uuid is the id and the first JSONL line (`session_meta`) repeats it with `cwd`. The notify payload carries it as `thread-id`.
- **Event:** only one, `agent-turn-complete`. Codex runs the program with the JSON as the **last argv argument** (not stdin), environment inherited:
  `{"type":"agent-turn-complete","thread-id":"<uuid>","turn-id":"<str>","cwd":"<abs>","input-messages":["..."],"last-assistant-message":"..."}`
  (`cwd` is present in recent versions; treat as optional.)
- **Not covered:** no event on turn start, on approval request or on exit. "working" and "needs you" stay on output matching and PTY exit, as the spec table says.

## Gemini CLI

- **Installed here:** no (`which gemini` empty). Everything below is from documentation already in context, not run. **Verify live.**
- **Per-launch hook:** yes, probably. Settings layers merge in this order: defaults, user `~/.gemini/settings.json`, project `.gemini/settings.json`, system. `geminiLaunch` writes `gemini-settings.json` into a fresh `mkdtemp` directory (`<tmpdir>/agentboard-XXXXXX`, 0700, file 0600) with `hooks` for `BeforeAgent`, `AfterAgent`, `Notification` and sets `GEMINI_CLI_SYSTEM_DEFAULTS_PATH` to it. That is the lowest-precedence layer and hook arrays merge by concatenation, so these hooks run alongside the user's, the project's and an admin's rather than replacing any (`GEMINI_CLI_SYSTEM_SETTINGS_PATH` would replace the admin file, so it is not used). If the variable is not honoured, fall back to the opt-in one-time edit of `.gemini/settings.json` with a diff.
- **Untrusted folders:** Gemini skips hooks defined in settings of an untrusted workspace (from source, not run). Whether that also covers hooks arriving through the defaults layer is unverified; if it does, a console in an untrusted folder shows no Gemini status from hooks and falls back to output matching.
- **Hook config shape:** `{"hooks":{"AfterAgent":[{"hooks":[{"type":"command","command":"\"<process.execPath>\" \"/abs/notify-relay.js\""}]}]}}`.
- **Resume:** `gemini --resume <session-id>` (`--resume latest` or an index also accepted; `--list-sessions` prints them).
- **Session id:** every hook payload has `session_id`; transcripts live in `~/.gemini/tmp/<project-hash>/chats/session-<timestamp>-<short-id>.json`. Gemini cannot be given an id at start, so capture it from the first hook payload (`BeforeAgent` fires at the first prompt) rather than from files.
- **Events and payload:** hooks receive JSON on **stdin**: `{"session_id","transcript_path","cwd","hook_event_name","timestamp", ...}` plus per event: `BeforeAgent`/`AfterAgent` add `prompt` (AfterAgent also `prompt_response`, `stop_hook_active`); `Notification` adds `notification_type` (for example `ToolPermission`), `message`, `details`. A hook must print JSON or nothing on stdout and exit 0 to not block.

## Relay

`notify-relay.js`: payload = `argv[2]` (Codex) else stdin (Gemini). POSTs `{ agent: $AGENTBOARD_AGENT, event: payload.type ?? payload.hook_event_name, payload }` to `$AGENTBOARD_URL/hook/$AGENTBOARD_CONSOLE_ID` (the daemon's hook body) with `authorization: Bearer $AGENTBOARD_TOKEN`, 2 s timeout, swallows every error (including unreadable stdin and bad JSON), exit 0. Both launchers set `AGENTBOARD_AGENT` and run the relay with `process.execPath`, so the hook works when `node` is not on the CLI's PATH.
