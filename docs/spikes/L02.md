# L02: PTY to WebSocket bridge, six shells

Machine: macOS (Darwin 25.6.0), Node 22.11.0, node-pty 1.1.0, ws 8.22.0, shell `/bin/sh` (bash 3.2 in sh mode).

## Reproduce

```
npm ci && npm run fix-pty
node --experimental-strip-types --no-warnings packages/daemon/spike/latency.ts
```

`latency.ts` starts `pty-ws.ts` as a child (random free port on 127.0.0.1), opens six sockets at once, types 200 characters into each one at a time and times send to echo.

## Numbers (three runs)

| run | p50 ms | p95 ms | max ms |
| --- | --- | --- | --- |
| 1 | 0.27 | 0.60 | 2.79 |
| 2 | 0.22 | 0.41 | 1.36 |
| 3 | 0.22 | 0.45 | 1.27 |

The p95 budget is 50 ms; it is met by two orders of magnitude (the first-ever run on a cold machine gave p95 1.97, max 6.65).

Memory (RSS): server idle about 81 MB, with six shells attached about 84 MB (the per-console Node-side cost is below RSS noise, under about 1 MB per console); the six `sh` processes add about 13.7 MB (2.3 MB each). Per shell cost is about 3 MB all in.

Two side checks (throwaway scripts, not committed):
- Resize: sending `{"cols":123,"rows":45}` then `stty size` printed `45 123`.
- Backpressure: with a client that stops reading and `yes | head -c 200000000` in the shell, server RSS grew 81 to 455 MB in 4 seconds (about 100 MB/s) because every pty chunk is `ws.send`-ed with no limit.

## For L11 (PTY manager) and L12 (server)

Latency is a non-issue, so do not add batching to chase it; the real risk is a console that floods output while a browser tab is slow, hidden or throttled. The spike has no backpressure and memory grows without bound, so L12 should check `ws.bufferedAmount` per socket and, above a high-water mark (say 1 MB), call `pty.pause()` and resume when it drains (L11's `PtyManager` should expose pause/resume, or the ring buffer should drop-and-mark instead of blocking the agent); one coalescing timer of a few ms per socket is cheap if frame count matters in the browser, not on the server. Resize works with a plain `p.resize(cols, rows)` and the kernel updates `stty size`; validate that cols and rows are positive integers (node-pty throws on garbage) and ignore resize messages from sockets that are not the writer. The wire format here (text frame = input, JSON `{cols,rows}` = resize) is ambiguous if the user pastes JSON, so the real protocol must use typed messages (L01's `t` field), not sniffing. Surprises: on macOS `/bin/sh` is bash 3.2 and emits readline's meta-key mode escape (`\e[?1034h`) before the prompt, so tests should match on substrings, never exact output; node-pty's darwin `spawn-helper` needs the execute bit with install scripts off; and the child exits when the socket closes only because the server calls `kill()` (SIGHUP), so L11 still needs the SIGKILL fallback for shells that ignore it.
