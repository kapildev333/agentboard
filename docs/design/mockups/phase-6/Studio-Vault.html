Tax rounding

ADR-0007 · accepted · see [[Xero export]], [[Checkout flow]]

Context

CAD orders with 13% HST drifted by a cent between our invoice total and what [[Xero export]] computed from line taxes. Xero rejects those invoices. The [[Reviewer]] console found it while reviewing [[Checkout flow]]'s diff on Oct 21.

Decision

Round half-even, per TaxLine, in minor units. Never round the order total; derive it. Implemented as roundHalfEven(value, 2) in src/tax/round.ts.

Consequences

  • Existing orders are unaffected; totals are recomputed on read.
  • Tests assert line-sum equality for every fixture; see [[Flaky tests]] for the one that depended on the old rounding.
  • Memory entry pushed to new consoles on request: [[Project memory · tax]] (not yet written).

Open

Does [[QuickBooks Online]] behave the same? X Reviewer suggested checking the sandbox before release.
